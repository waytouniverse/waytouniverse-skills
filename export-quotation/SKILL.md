# 中英双语外贸出口报价单生成器

把客户提供的**任意形式产品资料**转成一份可直接发送、可打印、带自动计算公式的 USD 出口报价单 `.xlsx`。

版式固定沿用 `assets/版式基准_中英双语出口报价单模板.xlsx`：抬头与买卖双方、报价信息、12 列商品明细、费用与总计、银行信息、5 条中英对照条款、双方签字栏；再加一页「填写指引 Guide」放公式清单、汇率核算和客户诉求跟进（内部页，发送客户前建议删除）。

## 何时使用 / 不适用

| 场景 | 处理 |
|---|---|
| 客户发来产品参数、规格表、采购清单、手写清单照片，要「按报价单出一份」 | ✅ 本技能 |
| 用户说「以后我把产品参数给你，你帮我出报价单」 | ✅ 本技能 |
| 只要一份**空白**报价单模板 | 直接复制 `assets/版式基准_中英双语出口报价单模板.xlsx`，不必跑脚本 |
| 软件项目功能清单 / 人天估算 / 飞书表格报价 | ❌ 用 `quote-generator` 技能 |
| 修改一份已有 xlsx 的内容 | ❌ 走 `workbuddy-sheetagent` 编辑链路 |

## 快速开始

```bash
SKILL=~/.workbuddy/skills/export-quotation

# 1) 把整理好的数据写成 JSON（字段见下）
# 2) 生成
python3 $SKILL/scripts/generate_quotation.py --input data.json --output "/path/客户名报价单_20261109.xlsx"
# 3) 交付前一键重算 + AIGC 标识 + 全链路校验（必须通过才能发）
python3 $SKILL/scripts/finalize.py --file "/path/客户名报价单_20261109.xlsx"
```

`finalize.py` 返回 `"status": "passed"` 才可交付；非零退出码就是有错误，必须修好再跑。

## 完整工作流

### 第 0 步：开工先读规矩（工作区有就必须读）
若当前工作目录存在 `规矩文档.md` 和 `踩坑日志.md`，先读，严格规避历史同类错误；收尾时把本次错误与用户修改要求**追加**到踩坑日志。

生成新工作簿属 `workbuddy-sheet-generation` 范畴，优先加载该技能取建表准则；本技能的 `finalize.py` 会自动定位它提供的 `recalc.py` / `aigc_label.py`（按版本号取最新）。

### 第 1 步：解析客户资料

输入可能是**图片、聊天文字、Excel/CSV、PDF、产品目录截图**。逐项转成结构化明细：

- **图片/手写清单**：先用 `sips -g pixelWidth -g pixelHeight <file>` 查真实像素尺寸再裁剪放大（环境通常没装 Pillow）。放大后逐行核对，不要凭缩略图猜字。
  - 引号 `"` / `〃` 表示「同上」，按上一行展开，并在备注里写明「ditto」；
  - 前导点、涂改、圈注一律**照录并加批注请用户核对**，不擅自改写数字；
  - 无法辨认的内容略去，并在 `transcription_notes` 里说明；
  - 用 `ViewImage` 分区域放大核对行对齐（品名 / 型号 / 数量 / 单价 / 备注）。
- **文字 / 表格 / PDF**：按列名映射到下方字段表；数字带 `$`、千分位、单位的先清洗成纯数值。
- **客户只给产品参数、没给单价**（常见）：`price` 填 `null`，单价与金额留空（浅黄填写区），公式会因空值保护返回空白，总计暂为 0。生成后必须在回复里明确告诉用户「N 项单价待填，填好自动重算」，**绝不替客户编价格**。可主动问一句是否有目标价。
- **只有中文品名**：英文品名由你翻译补齐（这是双语要求），但型号、规格、HS 编码、数量、单价一律照录，不推断、不编造。
- 资料没给的字段（HS 编码、毛重 CBM、公司/银行/联系人）一律留空或 `[ ]` 占位。
- 客户手写的商务诉求（议价、MOQ、包装、样品、交期）除录入明细外，全部整理进 `followups` 跟进清单，别丢在图片里。

### 第 2 步：查汇率（不许写死）
联网查**报价当日**官方中间价（如中国外汇交易中心人民币汇率中间价），把数值、日期、来源分别写入 `rate` / `rate_date` / `rate_source`。查不到就问用户，或让 `rate` 为 `null` 并在交付说明里明确提示「汇率待填」，**绝不沿用上次的值**。汇率只用于 CNY 参考金额，结算以 USD 为准。

### 第 3 步：写输入 JSON
照 `assets/example_input.json`（14 项五金真实案例）改。字段表见 `references/quotation_spec.md`。最少只需 `items`；其余留缺省由脚本按规矩处理。

### 第 4 步：生成与校验
跑第 1、3 条命令。`generate_quotation.py` 会打印锚点与 `expected`（预期货值、折扣、附加费、税额、总计、CNY 参考）；`finalize.py` 会逐行核对金额、序号、合计、有效期、卖方引用、Guide 页引用、公式是否仍在，并检查 AIGC 标识。

### 第 5 步：交付与回复
- 用 `present_files` 打开成品；**原空白模板保持不变**，客户版另存新文件。
- 回复里给出：明细项数、货值/GRAND TOTAL (USD)、CNY 参考、有效期至、校验结果；列出**待用户处理项**（`[ ]` 占位符、银行账号/SWIFT、缺失字段、单价待填、手写歧义）。
- 提醒：「填写指引 Guide」是内部页，发送客户前建议删除。
- 按用户自定义指令追加踩坑日志；用户提了修改要求也要一并记录。

## 硬性规矩（违反必出错）

1. **明细行数变化绝不原地插行**：openpyxl 不自动调整公式引用，会让合计/费用区全部错位。改 `items` 后由脚本按锚点重生成整份工作簿。
2. **顺序不能反**：先 `recalc.py` 再 `aigc_label.py`。重算会重写整个 xlsx 包，先写标识会被冲掉。
3. **公式必须带空值保护**：`IF(OR(...="",...),"",...)` 配合 `SUM()`，否则空单元格参与减法会出 `#VALUE!`。
4. **不编造**：公司名、地址、电话、银行账号、SWIFT、联系人、HS 编码、毛重、体积、单价——资料没有就留空或 `[ ]`，并在回复里点名。
5. **颜色语义**：浅黄＝填写区，浅蓝灰＝自动计算，深蓝＝表头与总计；所有 CSS 色值只能出现在 `xl_color()` 参数里并转成 `XL_` 常量。
6. **双语**：所有标签、条款、说明、批注均「中文 / English」对照。
7. **打印**：A4 横向、fitToWidth=1、fitToHeight=0、重复标题行 1:3；长文本不设固定行高，靠 `wrapText` 撑高。
8. 单格不要用 `merge_cells("E41:E41")`，用 `put()`（会报错风险）。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 序号列空白 | 序号公式 `=IF(COUNTA(B:C)=0,"",...)`，只有填了品名才显示编号，属预期 |
| 总计显示 $0.00 | 单价/数量待填，见「无单价模式」；补齐后自动重算 |
| `finalize.py` 找不到 recalc.py | 加载 `workbuddy-sheet-generation` 技能后重试；脚本在插件缓存目录按版本号自动选最新 |
| 客户要求让利 | 在**折扣率**栏填 0~1 的比例（浅黄输入区），不要直接改单价；总计与 CNY 参考自动重算 |
| 要加减明细行 | 改 JSON 的 `items` 后重跑生成脚本，再重跑 finalize |
| 要加客户诉求 | 写进 `followups`，Guide 页第 40 行起自动排布并带状态下拉 |
